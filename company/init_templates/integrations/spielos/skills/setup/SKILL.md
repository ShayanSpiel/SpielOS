name: setup
description: Start using SpielOS after installation, choose or create a company workspace, verify setup, and help with a missing supported Python runtime.
---

Welcome the user to SpielOS: a lasting company workspace for recurring AI work they can test and improve. Keep setup conversational. Do not ask the user to copy Python or CLI commands. Execute the supported bundled commands yourself through the host's local execution capability and explain the results in plain language.

Resolve the plugin root from this skill's installed file location: the folder containing plugin.json, scripts/ and runtime/. Use scripts/launch.sh from that actual root. Never guess a cache path or use a globally installed spielos executable. The bundled launcher performs no package installation or network download.

1. Ask whether the user wants an existing company folder or a new workspace, and get its explicit location. The current folder is a candidate only when the user selects it. Never create or select a home in the plugin directory, product source checkout, or another company's workspace. Explain that the company folder stays theirs when the plugin is updated or removed.
2. For an existing home, call select_company with its absolute path, then inspect_company. For a new home, run the bundled launcher with `init --dir <explicit absolute folder> -y --json`. The owner's setup request and folder selection authorize that creation; no separate round of confirmation is needed. Do not overwrite an existing folder's owner content or force a migration. Select and inspect the result through MCP.
3. If the launcher reports missing Python 3.11+, explain that desktop execution needs it. Offer to help install a supported interpreter using the user's normal package manager, with its normal approval controls. Do not silently download a runtime, weaken TLS verification or edit system Python. Native Windows is not supported; explain the limitation without claiming WSL qualification.
4. Explain that private local tracking retains supplied context, exposed tool events, final answers and reported usage in this company folder, and requests one bounded same-host review. No hidden reasoning is collected and nothing is exported by default. Run `setup-local-capture --home <selected absolute folder>` through the bundled launcher. It creates a local-only policy if none exists and preserves every existing policy. Report its actual capture/review/export state; if an existing policy disables capture, explain that setting instead of overwriting it. Respect an explicit user opt-out. Ask what the company does and which recurring job they want help with first. Record only explicit facts using supported profile/memory operations. Unknown facts stay unknown.
5. Open the dashboard using the bundled launcher's `report --home <selected home> --no-open --json` and give its returned clickable link. Explain that the private local link shows real records, not invented activity. Browser opening is appropriate when the user asks to see it.
6. Show the available skills: director for operating the company, dashboard for the report, help for usage, and the build/run/review workflow skills. In Codex these are explicit skill invocations (`$spielos:director`, `$spielos:dashboard`, `$spielos:help`, or the host's namespaced entries); do not promise custom native slash commands. The main chat is Director, not a separate agent to spawn. Offer one next step tied to the user's job. Existing workflows stay drafts until required evaluation, verified configured telemetry and independent review are complete. An evaluation pass is distinct from measured improvement.

No external service is connected by setup. Langfuse export needs an explicitly selected project and approved evidence policy. Credentials stay outside plugin files and company definitions. Sending, publishing and provider activation require their own exact authorization; Activepieces remains inactive.

If MCP is unavailable, use the bundled launcher for the same selected-home operations and report the missing tool connection. Do not route work through an unrelated plugin. Do not claim that installing a plugin automatically trusts company lifecycle hooks. Respect the host's normal hook review.


For the context/evaluation/usage experience, have the user open the selected company folder as their Codex workspace and review that home's shipped hooks using the host's normal controls. Verify an actual context receipt and Stop review request before saying capture is active. If hooks have not run or usage was not exposed, say so. At the end of meaningful work, render the runtime's concise Markdown tracking receipt with real dashboard/trace links, evaluation status and reported usage; do not invent rich host cards, billed cost or Langfuse confirmation. The dashboard, context, receipts and experiments all come from this same bundled SpielOS runtime, never from Karwise or another plugin.
