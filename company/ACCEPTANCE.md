# SpielOS acceptance contract

Product-facing concepts are Company, Workflow, Run and Improvement. GODAE is a
bounded development/change process. A production invocation never launches
unbounded pursuit or self-repair. The selected host owns wakeups and presentation.

Owner content belongs in the installed home's visible company/ tree. Source
contains only reusable code, neutral installation templates and synthetic cases.
Legacy evidence remains historical and readable. A reviewed migration produces
an exact, hash-bound operation manifest before any existing content moves. No
silent initialization, deletion, backups, external effects or permission grants.

The executable scenario catalog is tests/scenarios/spec.json. Every scenario
must be covered by successful behavior assertions and, where relevant, rendered
output inspection. A pass count over legacy mechanics is not release evidence.
The acceptance runner records actual test results and a source fingerprint; an
uncovered scenario, skipped test, changed source or unresolved external gate
prevents an overall completion claim.

Representative journeys:

- A founder creates a company, sees profile/strategy/brand/workflows rather than
  runtime internals, and later updates without losing a voice rule or template.
- An operations owner describes a weekly report, creates an agent with a skill,
  locks examples/rubric and dependencies, tests the real implementation on held
  cases, then releases it. A new production input is evaluated normally.
- A designer uses the company's actual pinned tokens, assets and layout template
  to produce a branded brief. Both harnesses consume the same brand revision;
  a missing asset, wrong theme or unreadable render blocks release.
- An agent builds on a cited operational lesson, honors an owner preference,
  and keeps unrelated or retired memory out of the next assignment. A new
  conversation restores durable work and the scoped context after a restart.
- A provider response is lost, a lease expires, a duplicate request arrives,
  or a callback is replayed. No external effect is blindly repeated; uncertainty,
  current execution ownership and the next recovery action remain visible.
- A team reviewer accepts quality and separately authorizes an exact action.
  A different principal, changed payload, wrong company or stale version is
  refused. A high average never masks a blocking criterion failure.
- An adopter inspects an immutable portable package, previews collisions and
  dependencies, imports without executing submitted Python, and can reproduce
  examples without developer-machine paths or bundled secrets.

Activepieces preparation is offline by default. Its documented
MCP skill/package can be prepared and validated, but live provider acceptance
stays explicitly deferred. Synthetic local qualification does not certify an
enterprise deployment, external account or compliance regime.
